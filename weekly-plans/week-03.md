## День 1 — Горутины, WaitGroup, утечки

- **Теория (40 мин):** горутина, планировщик GMP (обзорно), `GOMAXPROCS`,
  `sync.WaitGroup`, почему горутина «зависает» навсегда и как это выглядит.
- **Практика (90 мин):**
  - `Add` до старта горутины: правильный и неправильный вариант — сравни.
  - 10 маленьких программ: счётчик, параллельная сумма, `defer wg.Done()`.
  - Специально сделай утечку (горутина ждёт канал, который никто не закроет)
    и найди её тестом с `goleak`.
  - `runtime.NumGoroutine()` до и после.
- **Закрепление (30 мин):** Tour of Go — Goroutines; Go by Example — Goroutines, WaitGroup.
- **Проект (30 мин):** оберни `Check` в горутину для одного URL, дождись через `WaitGroup`;
  сделай срез результатов и защищённую запись.
- **Заметки:** почему `wg.Add` внутри горутины — гонка.

## День 2 — Каналы и pipeline

- **Теория (40 мин):** небуферизованные и буферизованные каналы, `close`,
  `for v := range ch`, направленные типы `chan<-`/`<-chan`, nil-канал,
  правило «закрывает тот, кто пишет».
- **Практика (90 мин):**
  - Producer/consumer: генератор чисел → обработчик → сбор результатов.
  - Pipeline из трёх стадий, каждая со своей горутиной.
  - Закрой канал и покажи панику при записи в закрытый канал.
  - Направленные каналы в сигнатурах функций.
  - Медленный потребитель и буфер: как меняется поведение при `cap=0/1/10`.
- **Закрепление (30 мин):** Go by Example — Channels, Channel Buffering, Channel Directions,
  Range over Channels.
- **Проект (30 мин):** сделай стадию `reader → checker → reporter` на каналах.
- **Заметки:** три вопроса: кто пишет, кто читает, кто закрывает.

## День 3 — select, fan-in/fan-out, worker pool

- **Теория (40 мин):** `select`, `time.After`, `time.NewTimer`, `default`,
  неблокирующие операции, fan-out/fan-in, worker pool, ограничение параллелизма.
- **Практика (90 мин):**
  - `select` с двумя каналами и таймаутом.
  - Fan-out: N воркеров читают из одного канала задач.
  - Fan-in: слияние N каналов в один.
  - Worker pool с `results` и `jobs`, закрытие корректное.
  - Отмена: `select { case <-ctx.Done(): return }` на каждой стадии.
- **Закрепление (30 мин):** [Go Blog — Pipelines and cancellation](https://go.dev/blog/pipelines).
- **Проект (30 мин):** реальный worker pool в P1: `-c N`, задачи из канала,
  сбор результатов, сохранение порядка вывода (индекс).
- **Заметки:** как отменять пайплайн, чтобы никто не остался заблокированным.

## День 4 — sync и atomic

- **Теория (40 мин):** `sync.Mutex`, `sync.RWMutex`, `sync.Once`, `sync/atomic`,
  когда `sync.Map` оправдан, почему нельзя копировать мьютекс, `go vet` про copylocks.
- **Практика (90 мин):**
  - Счётчик: сначала с гонкой (без синхронизации), поймай её `-race`.
  - Тот же счётчик на `Mutex` и на `atomic.Int64`; сравни бенчмарком.
  - Кэш на `RWMutex` с TTL.
  - `sync.Once` для инициализации клиента.
  - Передача мьютекса по значению → покажи, что блокировка не работает.
- **Закрепление (30 мин):** Go by Example — Mutexes; `go doc sync`, `go doc sync/atomic`.
- **Проект (30 мин):** счётчики успехов/ошибок в P1 через `atomic.Int64`
  без общего мьютекса.
- **Заметки:** почему «сначала race detector, потом оптимизация».

## День 5 — context, errgroup, semaphore

- **Теория (40 мин):** `context.Background/TODO`, `WithCancel`, `WithTimeout`,
  `WithDeadline`, `WithValue` (и почему значения — только request-scoped),
  `signal.NotifyContext`, `errgroup`, `semaphore`, `rate.Limiter`.
- **Практика (90 мин):**
  - `signal.NotifyContext(ctx, os.Interrupt, syscall.SIGTERM)`.
  - Отмена всех запросов при первом срабатывании сигнала.
  - `errgroup.WithContext`: первая ошибка отменяет остальные.
  - `semaphore.NewWeighted(10)` вместо пула горутин.
  - `rate.NewLimiter(rate.Limit(20), 5)` — ограничение RPS.
- **Закрепление (30 мин):** `go doc context`, `go doc golang.org/x/sync/errgroup`,
  `go doc golang.org/x/time/rate`; Tour of Go не нужен — читай документацию.
- **Проект (30 мин):** в P1: общий дедлайн на весь прогон, отмена по Ctrl+C,
  лимит RPS, таймаут на запрос.
- **Заметки:** почему `context` не хранят в структуре и передают первым аргументом.

## День 6 — Надёжность: ретраи, backoff, grace shutdown

- **Теория (40 мин):** идемпотентность ретраев, экспоненциальный backoff, jitter,
  какие ошибки ретраить (5xx, 429, сетевые), какие нет (4xx),
  graceful shutdown: `server.Shutdown(ctx)`.
- **Практика (90 мин):**
  - Ретраи только для идемпотентных запросов (GET).
  - Backoff с jitter, ограничение попыток.
  - Уважай `Retry-After`.
  - Убедись, что отмена контекста прерывает ожидание между попытками.
  - `time.NewTimer` + `defer timer.Stop()` вместо `time.After` в цикле.
- **Закрепление (30 мин):** Go by Example — Timers, Tickers; прочитай, как устроен
  `http.Client` timeout vs context deadline.
- **Проект (30 мин):** P1: флаг `-retries`, ретраи с backoff, в отчёте — число попыток.
- **Заметки:** какие ошибки нельзя ретраить и почему.

## Проект: P1 v2 — что добавляется

- [ ] `-c N` — ограниченный worker pool.
- [ ] `-deadline` — общий дедлайн, `-timeout` — на запрос.
- [ ] `-rps` — лимитер.
- [ ] `-retries` — backoff + jitter, только для ретраибельных ошибок.
- [ ] Отмена по SIGINT/SIGTERM, корректный выход.
- [ ] Exit code: `0` — все ок, `1` — есть ошибки, `2` — ошибка конфигурации.
- [ ] Тесты: `-race`, `goleak`, фейковый медленный сервер, тест отмены.
- [ ] Бенчмарк и раздел «Производительность» в README.

## Типичные ошибки недели

- `wg.Add(1)` внутри горутины.
- Запись в закрытый канал или закрытие канала читателем.
- Горутина, которая навсегда ждёт канал после ошибки.
- `time.After` в цикле — накопление таймеров.
- Ретраи без ограничения и без jitter → «стадо».
- `context.Background()` внутри функции вместо проброса.
- Мьютекс, скопированный по значению.
- `sync.Map` там, где хватит обычной мапы под `RWMutex`.
