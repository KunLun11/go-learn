# Неделя 8 — Capstone, ревью, подготовка к интервью

[← Неделя 7](week-07.md) · [Оглавление](README.md)

> **Цель:** собрать портфолио-сервис, провести честное саморевью и проверить себя
> на вопросах уровня middle.
> **Проект:** P4 — эволюция P2+P3 в один связный сервис.
> **Бюджет:** ~18 часов.

## Итоги недели

- [ ] Один репозиторий: `cmd/api`, `cmd/worker`, общие пакеты, чистая структура.
- [ ] Функциональная полнота: фильтры, поиск, пагинация, аудит, лимиты.
- [ ] Все тесты зелёные, `-race`, линтер, CI.
- [ ] README: архитектура, запуск, решения, компромиссы, «что дальше».
- [ ] Нагрузочный отчёт и хотя бы одна осознанная оптимизация.
- [ ] Пройден mock-интервью по 30 вопросам без подглядывания.
- [ ] Записан план на следующие 3 месяца.

---

## День 1–2 — Слияние проектов

- **Теория (40 мин):** границы пакетов, общий домен, как не тащить `httpapi` в воркер,
  где живут интерфейсы, что вынести в `internal/platform`.
- **Практика (4–5 часов):**
  - Один модуль, два `main`, общие `internal/store`, `internal/service`, `internal/config`.
  - Убери дублирование: конфиг, логгер, метрики, БД, Redis — по одному месту.
  - Воркер использует те же сервисы, что и API.
  - Проверь, что нет циклических импортов и «god package».
- **Закрепление:** `go list -deps ./... | wc -l`, `go mod graph` — оцени сложность.
- **Проект:** коммит «merge P2+P3», зелёные тесты.
- **Заметки:** какие интерфейсы оказались лишними.

## День 3 — Функциональные пробелы

- **Теория (40 мин):** что делает сервис «продуктовым»: поиск, фильтры, сортировка,
  пагинация, аудит, лимиты, корректные ошибки, идемпотентность.
- **Практика (4 часа):**
  - Полнотекстовый поиск (Postgres `tsvector` или `ILIKE` с индексом — осознанно).
  - Фильтры и сортировка с whitelist полей (никакой конкатенации SQL).
  - Аудит: кто и что изменил.
  - Лимиты: размер тела, число задач на пользователя, rate limit.
  - Проверка всех error-path: 400/401/403/404/409/422/429/500.
- **Закрепление:** пройди чеклист production readiness из основного плана.
- **Проект:** фича-коммиты с тестами.
- **Заметки:** какие ограничения добавил и почему.

## День 4 — Саморевью

- **Теория (40 мин):** чеклист ниже; читай свой код как чужой.
- **Практика (4 часа):**
  - Пройди файлы по одному, помечай проблемы.
  - Удали мёртвый код, `TODO`, неиспользуемые зависимости (`go mod tidy`).
  - Проверь обработку каждой ошибки: не потеряна, не залогирована дважды.
  - Проверь, что нет `panic` вне границ, `init()`, глобального состояния.
  - `go test -cover`, найди непокрытые критичные ветки.
- **Закрепление:** сравни с [Go Code Review Comments](https://go.dev/wiki/CodeReviewComments)
  и [Effective Go](https://go.dev/doc/effective_go).
- **Проект:** PR «self-review fixes» с описанием найденного.
- **Заметки:** три вещи, которые сделал бы иначе с самого начала.

### Чеклист саморевью

- [ ] Пакеты названы по смыслу, без `utils`, `common`, `helpers`.
- [ ] Интерфейсы маленькие и на стороне потребителя.
- [ ] Ошибки обёрнуты `%w`, проверяются `Is/As`, не теряются.
- [ ] Все внешние вызовы с `context` и таймаутом.
- [ ] Нет горутин без пути завершения.
- [ ] Нет копирования мьютексов.
- [ ] SQL: параметры, явные колонки, `rows.Close`, `ErrNoRows`.
- [ ] HTTP: лимиты тела, таймауты, закрытие Body.
- [ ] Секретов нет в коде, логах и ответах.
- [ ] Тесты проверяют поведение, а не реализацию.
- [ ] Есть тесты на отказные сценарии.
- [ ] README позволяет запустить проект с нуля.
